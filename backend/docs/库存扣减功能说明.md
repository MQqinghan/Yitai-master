# 库存扣减与销量增加功能实现说明

## 功能概述
实现了用户购买商品付款后，自动减少商品库存并增加销量的功能。

## 实现流程

### 1. 支付回调触发
当支付宝异步回调通知支付成功时，触发以下流程：
- 入口：`AlipayController.alipayNotify()` 
- 路径：`/api/order/alipay/callback/notify`

### 2. 更新支付状态
在 `PaymentInfoServiceImpl.updatePaymentStatus()` 中：
1. 验证签名和支付状态
2. 更新支付记录状态为已支付
3. 调用订单服务更新订单状态
4. **遍历订单明细，对每个商品执行：**
   - ✅ 增加销量：`productFeignClient.updateSaleNum(skuId, num)`
   - ✅ 扣减库存：`productFeignClient.deductStock(skuId, num)` **[新增]**

### 3. 数据库操作

#### 扣减库存SQL（ProductSkuMapper.xml）
```xml
<update id="deductStock">
    update product_sku
    set stock_num = stock_num - #{num}
    where id = #{skuId}
    and stock_num >= #{num}
</update>
```

**关键特性：**
- 使用 `stock_num >= #{num}` 条件确保库存充足才扣减
- 返回受影响行数，如果返回0表示库存不足

#### 增加销量SQL（ProductSkuMapper.xml）
```xml
<update id="updateSaleNum">
    update product_sku
    set sale_num = sale_num + #{num}
    where id = #{skuId}
</update>
```

## 数据一致性保证

### 1. 下单时预校验
在 `OrderInfoServiceImpl.submitOrder()` 中：
- 提交订单前检查库存是否充足
- 如果库存不足，抛出异常阻止下单

### 2. 支付时再次扣减
在支付成功后：
- 通过SQL条件 `stock_num >= #{num}` 确保不会超卖
- 如果扣减失败（返回false），记录错误日志

### 3. 幂等性保证
- 支付回调有幂等性检查（paymentStatus==1时直接返回）
- 避免重复扣减库存和重复增加销量

## 日志监控

### 成功场景
正常情况下不会有特殊日志输出。

### 失败场景
如果库存扣减失败，会在控制台输出：
```
库存扣减失败: skuId=xxx, num=xxx
```

**注意：** 理论上不应该出现这种情况，因为：
1. 下单时已经校验过库存
2. SQL中有 `stock_num >= #{num}` 保护

如果出现此日志，需要排查：
- 是否有手动修改数据库库存
- 是否有其他途径扣减库存
- 是否存在并发问题

## 注意事项

1. **事务管理**：当前实现在支付回调中依次调用，如果需要强一致性，可以考虑使用分布式事务（如Seata）

2. **性能优化**：每次支付都会逐个更新SKU，如果订单商品很多可能影响性能，可以考虑批量更新

3. **库存恢复**：如果订单取消或退款，需要实现库存恢复逻辑（当前未实现）

4. **Redis缓存**：如果使用了Redis缓存商品信息，扣减库存后需要同步更新缓存

## 扩展建议

### 1. 实现库存恢复
在订单取消时恢复库存：
```java
// OrderInfoServiceImpl.cancelOrder()
public void cancelOrder(String orderNo) {
    // ... 更新订单状态
    
    // 恢复库存和减少销量
    OrderInfo orderInfo = getOrderInfoByOrderNo(orderNo);
    for (OrderItem item : orderInfo.getOrderItemList()) {
        // 恢复库存
        productFeignClient.restoreStock(item.getSkuId(), item.getSkuNum());
        // 减少销量
        productFeignClient.reduceSaleNum(item.getSkuId(), item.getSkuNum());
    }
}
```

### 2. 添加库存预警
当库存低于阈值时发送通知：

if (stockNum < THRESHOLD) {

### 3. 使用乐观锁
在高并发场景下，可以使用版本号机制：
```xml
<update id="deductStockWithVersion">
    update product_sku
    set stock_num = stock_num - #{num},
        version = version + 1
    where id = #{skuId}
      and stock_num >= #{num}
      and version = #{version}
</update>
```
