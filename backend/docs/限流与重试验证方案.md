# Gateway限流与OpenFeign重试机制验证方案

## 一、测试目标

验证Spring Cloud Gateway的限流策略和OpenFeign的重试机制在高并发场景下的有效性。

## 二、配置说明

### 2.1 Gateway限流配置

**限流算法**: Redis + 令牌桶算法（Token Bucket）

**限流参数**:
- `replenishRate`: 100 req/s（令牌填充速率）
- `burstCapacity`: 200（令牌桶容量，允许短时峰值）
- `requestedTokens`: 1（每次请求消耗1个令牌）
- `key-resolver`: 基于请求路径限流

**工作原理**:
1. 每个API路径独立维护一个令牌桶
2. 每秒向桶中添加100个令牌
3. 桶的最大容量为200个令牌
4. 每个请求消耗1个令牌
5. 当令牌不足时，返回HTTP 429（Too Many Requests）

### 2.2 OpenFeign重试配置

**重试参数**:
- `connectTimeout`: 5000ms（连接超时）
- `readTimeout`: 10000ms（读取超时）
- `maxAttempts`: 3次（最大重试次数）
- `period`: 100ms（初始重试间隔）
- `maxPeriod`: 1000ms（最大重试间隔）

**工作原理**:
1. 当Feign调用失败（网络异常、超时等）时自动重试
2. 采用指数退避策略：100ms → 200ms → 400ms → 800ms
3. 最多重试3次，总耗时不超过2秒
4. 仅对可重试的异常进行重试（如连接超时、读取超时）

### 测试1: Gateway限流机制验证

#### 3.1.1 测试目的
验证Gateway在超过限流阈值时能够正确拒绝请求，保护后端服务。

#### 3.1.2 测试步骤

**步骤1: 重启Gateway服务使配置生效**
```powershell

mvn spring-boot:run
```

**步骤2: 执行高并发测试（超过限流阈值）**
```powershell

E:\jmeter\apache-jmeter-5.6.3\bin\jmeter.bat -n -t "E:\毕设\代码\代码\后端\代码\glxt-hou\pressure_test_plan.jmx" -Jthreads=500 -Jloops=100 -Jrampup=10 -l "E:\毕设\压力测试\results\result_rate_limit.csv" -e -o "E:\毕设\压力测试\results\report_rate_limit"
```

**步骤3: 观察测试结果**
- 查看HTTP响应码分布
- 统计429状态码的数量
- 分析被限流的请求比例

#### 3.1.3 预期结果

✅ **成功标志**:
- 部分请求返回HTTP 429状态码
- 错误日志中出现"RateLimiter"相关记录
- Redis中存在限流相关的key（可通过Redis客户端查看）
- 后端服务没有被压垮，正常运行

❌ **失败标志**:
- 所有请求都成功（限流未生效）
- 后端服务崩溃或响应极慢

#### 3.1.4 验证方法

**方法1: 查看JMeter报告**
打开HTML报告，查看"Response Codes"图表，应该看到429状态码。

**方法2: 查看Gateway日志**
```

```

**方法3: 查看Redis中的限流数据**

### 测试2: OpenFeign重试机制验证

#### 3.2.1 测试目的
验证当服务调用失败时，OpenFeign能够自动重试，提高成功率。

#### 3.2.2 测试步骤

**步骤1: 模拟服务临时故障**

创建测试接口，模拟随机失败：

```java
// 在service-user的Controller中添加测试接口
@GetMapping("/api/user/test/retry")
public Result<String> testRetry() {
    // 模拟50%的失败率
    if (Math.random() < 0.5) {
        throw new RuntimeException("模拟服务临时故障");
    }
    return Result.build("成功", ResultCodeEnum.SUCCESS);
}
```

**步骤2: 通过Feign调用该接口**

在service-cart中创建测试接口：
```java
@GetMapping("/api/order/cart/test/feign-retry")
public Result<String> testFeignRetry() {
    // 调用user服务的测试接口
    String result = userFeignClient.testRetry();
    return Result.build(result, ResultCodeEnum.SUCCESS);
}
```

**步骤3: 执行多次调用测试**
```powershell
# 使用JMeter或脚本执行100次调用
for ($i = 1; $i -le 100; $i++) {
    Invoke-WebRequest -Uri "http://localhost:8500/api/order/cart/test/feign-retry" -UseBasicParsing | Select-Object StatusCode
}
```

**步骤4: 观察重试日志**
```
[Feign重试] 第1次重试: service-user/test/retry
[Feign重试] 第2次重试: service-user/test/retry
[Feign重试] 调用成功（经过2次重试）
```

#### 3.2.3 预期结果

✅ **成功标志**:
- 最终成功率明显高于单次调用成功率
- 日志中显示重试记录
- 重试间隔符合指数退避策略（100ms → 200ms → 400ms）

❌ **失败标志**:
- 没有重试日志
- 第一次失败后直接返回错误

#### 3.2.4 简化验证方法（无需修改代码）

**方法: 手动停止service-user服务**

1. 启动service-cart服务
2. 调用需要Feign远程调用的接口（如保存消息）
3. 在调用过程中突然停止service-user服务
4. 观察service-cart的日志，应该看到重试记录
5. 重新启动service-user服务
6. 观察后续调用是否成功

## 四、数据收集与分析

### 4.1 需要收集的数据

1. **Gateway限流数据**:
   - 被限流的请求数量
   - 429状态码占比
   - 限流触发时间点

2. **OpenFeign重试数据**:
   - 重试触发的次数
   - 重试成功的次数
   - 平均重试次数 per 请求

3. **系统稳定性数据**:
   - CPU使用率
   - 内存使用情况
   - 数据库连接数
   - Redis连接数

### 4.2 数据分析方法

**限流效果分析**:
```
限流有效率 = (429请求数 / 总请求数) × 100%
```

**重试成功率分析**:
```
重试成功率 = (重试后成功数 / 总重试数) × 100%
系统容错提升 = (有重试成功率 - 无重试成功率) / 无重试成功率 × 100%
```

## 六、注意事项

⚠️ **重要提醒**:

1. **限流参数调整**: 
   - 当前配置为100 req/s，适合测试
   - 生产环境需要根据实际业务调整

2. **重试次数控制**:
   - 过多重试会增加系统负载
   - 建议3-5次为宜

3. **监控告警**:
   - 实时监控429错误率
   - 当限流频繁触发时需要扩容

4. **幂等性保证**:
   - 重试的请求必须是幂等的
   - 避免重复提交订单等问题
